Visão Geral do Produto

A7X Comercial é um CRM SaaS multi-tenant focado em equipes de vendas B2B que gerenciam carteiras de clientes com contratos recorrentes. O produto combina gestão operacional de clientes (contas, contratos, documentos) com automação comercial via WhatsApp e um motor de inteligência que prioriza ações de alto impacto.

PRD — Requisitos do Produto

Problema que resolve

Equipes comerciais B2B perdem receita por falta de visibilidade sobre quais clientes precisam de atenção imediata. CRMs genéricos não priorizam ações, não integram com WhatsApp de forma nativa e não geram alertas automáticos de contratos vencendo. O A7X resolve isso com um sistema de execução guiada: o vendedor abre o app e já sabe exatamente o que fazer.

Módulos & Features

🎯 Execução (/execution)

Motor de regras declarativo que transforma dados de contas, contratos e deals em uma fila priorizada de ações. Cada regra tem: condição de match, tipo de ação, score base e razão. A fila é reordenada por score total (urgência + valor).

Tipo de açãoTrigger
follow_upCliente sem contato por N dias
reactivationCliente inativo em pipeline
renewalContrato vencendo em <30 dias
upsellCliente ativo com sinal de expansão
proposalDeal em estágio avançado sem proposta enviada

💬 Inbox WhatsApp (/inbox)

Interface de mensagens agrupadas por contato com mapeamento número → conta. Exibe conversas recebidas via webhook Meta. Operadores podem responder diretamente. Comando "feito"/"ok" detectado automaticamente como action_taken.

📊 Pipeline & Deals (/deals, /pipeline)

Kanban de negócios com 6 estágios: lead → in_service → quote_sent → negotiating → closed → recurring. Cada deal tem valor estimado, account vinculada, e histórico de mudanças de estágio. Deals parados por 14+ dias são priorizados na fila de execução.

📣 Campanhas (/campaigns)

Construção de campanhas com audiências pré-definidas (inativos 30d, em risco, oportunidade de upsell, renovação próxima etc.) e templates de mensagem variantes (formal/casual/breve). Campanhas disponíveis a partir do plano Pro (20/mês) e ilimitadas no Scale.

📋 Contratos (/contracts)

Gestão completa de contratos com valor, moeda, datas, auto-renew e notas. Status derivado automaticamente: draft → active → expiring → expired → cancelled. Cron diário gera alertas para contratos expirando em <30 dias.

🤖 Inteligência Comercial

Funções puras (sem side effects) que derivam insights a partir dos dados:

FunçãoOutput
CommercialScorehot / warm / cold / at_risk / upsell
NextBestActionAção recomendada com contexto
OpportunitySignalSinais de expansão identificados
MessageSuggestionTemplate sugerido por contexto
RiskClassificationNível de risco: low / medium / high / critical
LTVComputationLifetime Value a partir de contratos

🏢 Portal B2B (/portal-clients)

Portal de autoatendimento para clientes finais acessarem contratos, documentos e faturas. Gerenciado pelo tenant; acesso por link direto sem criação de conta completa.

API Routes

GET /api/accounts/search

Busca textual de contas para componentes autocomplete. Respeita RLS — retorna só contas do tenant autenticado.

// Query params
q=string      // termo de busca
limit=number  // máx 50, default 20
status=string // filtro por status

// Response
[{ id, name, status, segment }]

POST /api/stripe/checkout

Cria sessão Stripe Checkout para upgrade de plano. Retorna URL para redirect.

// Body
{ plan: "pro" | "scale" }

// Response
{ url: string }  // URL do Stripe hosted checkout

POST /api/stripe/webhook

Recebe eventos Stripe. Verifica assinatura HMAC. Atualiza tabela subscriptions.

// Eventos tratados:
checkout.session.completed       → nova assinatura
customer.subscription.updated    → mudança de plano / renovação
customer.subscription.deleted    → cancelamento
invoice.paid                     → atualiza current_period_end

POST /api/whatsapp/send

Envia mensagem WhatsApp via Meta Cloud API. Armazena audit trail antes de chamar a API.

// Body
{
  account_id: string
  phone: string
  message: string
  action_type?: "follow_up" | "upsell" | "reactivation" | "proposal" | "renewal"
}

// Retry: 3 tentativas com backoff 1s → 3s → 10s
// Side effects no sucesso: last_contact_at, pipeline_stage, timeline

POST & GET /api/whatsapp/ingest

Webhook Meta para mensagens recebidas. Suporta dois modos de auth:

// Auth mode 1: Meta HMAC (X-Hub-Signature-256)
// Auth mode 2: Internal API key (x-api-key header)

// GET: verificação do webhook (hub.challenge)
// POST: ingest de mensagens + status updates
// Idempotência: skip por wa_message_id duplicado

GET /api/cron/generate-alerts

Executa diariamente às 08:00. Gera alertas de contratos vencendo para todos os tenants.

GET /api/cron/digest

Executa diariamente às 08:05. Envia resumo operacional via WhatsApp para o número configurado.

Multi-tenancy & RLS

A isolação de dados é garantida em duas camadas: na aplicação (queries sempre filtradas por tenant_id) e no banco (RLS policies que impedem acesso mesmo em caso de bug na aplicação).

Função central de segurança

-- Retorna os tenant_ids do usuário autenticado
CREATE FUNCTION public.my_tenant_ids()
RETURNS uuid[]
AS $$
  SELECT ARRAY(
    SELECT tenant_id FROM tenant_users
    WHERE user_id = auth.uid()
  )
$$ LANGUAGE sql SECURITY DEFINER;

-- Exemplo de policy usando a função:
CREATE POLICY "tenant_isolation" ON accounts
  USING (tenant_id = ANY(public.my_tenant_ids()));

RolePermissões

adminAcesso total, pode editar organização
memberAcesso operacional (contas, deals, inbox)

Padrão em server actions

async function updateOrganizationName(tenantId, name) {
  // 1. Verificar usuário autenticado
  const { data: { user } } = await supabase.auth.getUser()
  if (!user) return { error: "Não autenticado" }

  // 2. Verificar pertencimento ao tenant
  const { data: membership } = await supabase
    .from("tenant_users")
    .select("role")
    .eq("tenant_id", tenantId)
    .eq("user_id", user.id)
    .single()

  // 3. Verificar role mínimo exigido
  if (!membership) return { error: "Acesso negado" }
  if (!["owner", "admin"].includes(membership.role))
    return { error: "Permissão insuficiente" }

  // 4. Usar service client (bypassa RLS com autorização verificada)
  const service = createServiceClient()
  await service.from("tenants").update({ name }).eq("id", tenantId)
}

Feature gates

// billing-guard.ts — verificado antes de criar conta ou campanha
async function checkAccountLimit(tenantId) {
  const limits = getEffectiveLimits(plan, status)
  if (limits.maxAccounts === -1) return { allowed: true }
  const count = await getAccountCount(tenantId)
  return {
    allowed: count < limits.maxAccounts,
    reason: `Limite de ${limits.maxAccounts} contas atingido`
  }
}

Integração WhatsApp Business

Arquitetura

Integração via Meta Cloud API (WhatsApp Business API v20+). Credenciais armazenadas por tenant na tabela whatsapp_integrations com fallback para variáveis de ambiente globais.

→

Envio (Outbound)

App → POST /api/whatsapp/send → Meta Cloud API → update status em whatsapp_messages

←

Recebimento (Inbound)

Meta → POST /api/whatsapp/ingest → resolve tenant → store message → update account timeline

Segurança do webhook

// Verificação HMAC obrigatória para payloads Meta
const sig = request.headers.get("x-hub-signature-256")
const expected = "sha256=" + hmac(body, WHATSAPP_APP_SECRET)
if (sig !== expected) return Response.json({ error: "Unauthorized" }, { status: 401 })
